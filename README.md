# つみつみ

## 概要

つみつみは、タスクや予定を登録し、忙しさや余裕のなさを「つみ度」として可視化するWebアプリケーションです。

課題・予定・やることが増えると、自分がどのくらい忙しい状態なのかを把握しづらくなります。本アプリでは、タスクや予定を整理し、現在の状況を分かりやすく表示することで、計画的な行動をサポートします。

## 主な機能

* タスクの登録
* タスク一覧の表示
* 予定の登録
* 予定一覧の表示
* つみ度の表示
* 性格診断による表示内容の調整

## 使用技術

* React
* TypeScript
* Vite
* Git / GitHub

## 開発環境の準備

このプロジェクトを動かすには、Node.js が必要です。

Node.js が入っているか確認するには、ターミナルで以下を実行してください。

```bash
node -v
```

npm が入っているか確認するには、以下を実行してください。

```bash
npm -v
```

バージョン番号が表示されれば準備完了です。

## セットアップ方法

初めてこのプロジェクトを使うときは、以下のコマンドを実行してください。

```bash
npm install
```

これは、アプリを動かすために必要なパッケージをインストールするコマンドです。

## 起動方法

開発用サーバーを起動します。

```bash
npm run dev
```

実行後、ターミナルに表示されるURLをブラウザで開いてください。

通常は以下のようなURLが表示されます。

```txt
http://localhost:5173/
```

## 基本的な開発の流れ

作業を始める前に、まず `develop` ブランチを最新の状態にします。

```bash
git checkout develop
git pull origin develop
```

次に、自分の作業用ブランチを作成します。

```bash
git checkout -b feature/作業内容
```

例：

```bash
git checkout -b feature/home-screen
```

作業が終わったら、変更内容を確認します。

```bash
git status
```

変更したファイルを追加します。

```bash
git add .
```

コミットします。

```bash
git commit -m "変更内容を簡潔に書く（詳しくは下記のコミットメッセージの例を参照）"
```

GitHubにプッシュします。

```bash
git push -u origin ブランチ名
```

その後、GitHub上でPull Requestを作成します。

## ブランチ運用

このプロジェクトでは、以下のようにブランチを使い分けます。

* `main`：完成版・提出用のブランチ
* `develop`：開発の基準となるブランチ
* `feature/○○`：機能追加用のブランチ
* `docs/○○`：READMEや設計書など、ドキュメント修正用のブランチ
* `fix/○○`：不具合修正用のブランチ

例：

```txt
feature/home-screen
feature/add-goal
docs/update-readme
fix/calc-progress
```

## コミットメッセージの例

コミットメッセージは、何をしたか分かるように書きます。

例：

```txt
READMEを更新
ホーム画面を作成
目標追加フォームを作成
達成率の計算処理を追加
```

必要に応じて、以下のように種類を付けてもよい。というかこっちを推奨。

```txt
追加: ホーム画面を作成
修正: 達成率の計算ミスを修正
更新: READMEを更新
環境構築: React・TypeScriptを導入
```

## Pull Requestについて

作業が終わったら、直接 `develop` に反映せず、Pull Requestを作成します。

Pull Requestには、以下の内容を書くと分かりやすいです。

```md
## 概要
変更内容を簡単に書く

## 変更内容
- 変更したこと
- 追加したこと
- 修正したこと

## 動作確認
- 確認した内容を書く
```

## 注意点

* `main` や `develop` に直接コミットしない
* 作業前に必ず `develop` を最新にする
* 1つのブランチでは、なるべく1つの作業だけを行う
* 変更内容が大きくなりすぎる前にPull Requestを作成する
* 分からない場合は、無理に進めずチーム内で確認する
